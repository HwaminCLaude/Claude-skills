# model-flow-html

모델 하나를 **실제 모양 그대로, 처음부터 끝까지** 보여 주는 단일 HTML 페이지를 만든다. 모델 구조를 위에서 아래로 펼쳐 두고, 예시 입력 하나가 줄기를 타고 층마다 내려가는 과정을 단계별로 따라간다. 형식은 bbycroft.net/llm이고, 내용은 사용자의 모델과 학습 방식(LoRA 등)이다.

사용자에게는 한국어로 답한다. 코드 식별자는 영어, 페이지 글은 한국어 습니다체.

## 결과물

- **페이지 하나**: Artifact용 HTML 조각(fragment). Artifact 도구가 있으면 비공개 링크로 게시한다. 같은 내용의 독립 실행 사본(`<name>.html`, doctype 포함)도 함께 둔다.
- **화면 배치**:
  - 왼쪽 레일: 논문식 블록 구조도(누르면 그 자리로 이동, 잔차 연결은 옆길로 표시, 블록마다 값 개수), 단계 제목·해설·출처, 아래에 붙은 이전/다음 단추.
  - 오른쪽 판: 모델 전체의 입체 그림. 끌기로 돌리고, 휠·핀치로 확대하고, Shift+끌기로 옮기고, ← →로 단계를 넘긴다. 부품에 마우스를 올리면 정확한 모양과 개수가 뜬다. 범례의 조건 단추로 어댑터를 붙였다 뗀다.
  - 좁은 화면(820px 이하)에서는 판이 위, 레일이 아래로 간다. 판 위의 작은 글자는 숨으므로 입력·softmax 단계의 예시 문장은 엔진이 레일에 한 번 더 보인다.
- **세 가지 색**: 파랑 = 원래 모델의 가중치(학습할 때는 얼린 값), 보라 = 흐르는 값과 잔차 줄기, 조건 색 = LoRA. RoPE와 어텐션 계산처럼 학습하는 값이 없는 연산은 회색이다. 로짓과 softmax 확률은 흐르는 값이라 보라다.

## 그리는 원칙 — 반드시 지킨다

이런 페이지에서 가장 흔한 실수 두 가지를 막는 규칙이다.

1. **"이 페이지처럼"은 참고 페이지의 구조를 따르라는 뜻이다.** 이전 산출물(영상의 장면 배치, 파이프라인 도식)을 웹으로 옮기지 않는다. 판 위에 놓이는 것은 **모델 자체**이고, 값이 그 구조를 따라 위에서 아래로 내려간다.
2. **실제 전체 구조를 그린다.** 층 1만 자세히 그리고 나머지 층을 작은 타일로 줄이지 않는다.
   - 층 2~N도 층 1과 **같은 상세도**로 다 그린다. 규모는 카메라(멀리서 보기, 층 훑기, 이름표 간추리기, LOD)로 다룬다.
   - 정규화(norm)는 실제 자리에 둔다. pre-norm 모델은 가지마다 하나씩 있고 줄기에는 없으며, 마지막 norm이 하나 더 있다.
   - 잔차 더하기는 줄기 위의 마디로, 잔차 연결은 구조도에서 옆으로 돌아가는 길로 그린다.
   - 어텐션 안(q·k·v, RoPE, 마스크드 어텐션, o)과 MLP 안(gate·up → act × up → down)을 빠짐없이 그린다.
   - **얼린 값이 보이게 한다.** 원래 모델의 행렬은 진한 파랑, 실제 비율, 실제 축척의 모눈이다. 층마다, 그리고 전체로 얼린 값의 개수를 적는다.
   - **LoRA는 해당 선형층 W₀의 바로 오른쪽에 붙인다.** B는 세로로 긴 띠(d_out × r), A는 가로로 넓은 띠(r × d_in)다. 대상이 아닌 선형층에는 붙이지 않는다.
3. **빠진 것이 없느냐는 질문을 받으면** 고치기 전에 무엇을 그렸고 무엇을 안 그렸는지부터 솔직하게 답한다.

## 작업 흐름

### 0. 입력 모으기

- 모델 정보는 config.json 하나면 된다(로컬 HF 캐시의 `snapshots/<rev>/config.json`이나 사용자가 준 파일). 모델 이름만 받았으면 이미 아는 공개 수치를 쓰되, 1단계에서 공개 합계로 대조한다.
- 학습 방식: LoRA 여부, r, α, 대상 모듈, 양자화(QLoRA면 4비트 NF4 등), 비교 조건(어댑터 여러 벌이면 조건마다).
- 논문·코드에서 읽을 것: 전체 파라미터 수(대조용), 입력 형식(대화 틀, system 프롬프트), 학습 손실을 어디에 거는지, 평가 결과 표. **결과 숫자는 논문 표에서만** 가져온다.
- 비공개 자료는 열지 않는다. 이용 조건이 붙은 데이터셋이나 개인 정보가 든 원본은 보지도 화면에 내지도 않는다. 예시 입력은 논문에 실린 합성 예시나 새로 쓴 중립 예시로 한다.

### 1. 수치 확정 — 손으로 쓰지 않는다

```bash
node scripts/params.mjs --config <config.json 또는 모델 폴더> --lora r=16,alpha=32,targets=q,k,v,o,gate,up,down --expect total=<논문의 전체 수>,trainable=<논문의 학습 수>
python scripts/count_tokens.py --model <토크나이저가 있는 폴더> --messages <messages.json> --template-kwargs '{"date_string":"26 Jul 2024"}'
```

- `params.mjs`는 템플릿 안의 계산 블록(`<mf:count>`)을 그대로 불러와 모듈별·층별·전체 개수와 LoRA 개수를 내고, 붙여 넣을 `MODEL`·`LORA` 블록을 찍는다. `--expect`가 어긋나면 exit 1이다. 어긋나면 config 해석(bias, tied, head_dim)부터 다시 본다. 논문 수치를 페이지에 그냥 적어 넣어 맞추지 않는다.
- `count_tokens.py`는 실제 토크나이저와 대화 틀로 system·user·틀·목표 토큰 수를 잰다. 토큰 수를 어림하지 않는다. Llama 3 계열 틀처럼 날짜가 들어가는 틀은 `date_string`을 고정해 결과가 매번 같게 한다(틀이 쓰지 않는 인자면 `참고:` 줄로 알린다). 채팅 틀이 없는 기본 모델(GPT-2 등)은 `--plain`으로 잰다(system 0, template은 토크나이저가 붙이는 BOS 수라 GPT-2는 0). 그 블록에는 `plain: true`가 붙어 페이지 글이 '채팅 템플릿'을 말하지 않는다.
- `--model`에는 허브 캐시의 `models--<org>--<name>` 폴더를 그대로 줘도 된다(`snapshots/<rev>`로 푼다).
- messages에 system이 없을 때 틀이 기본 system 글을 넣으면(Qwen2.5 등) `참고:` 줄로 그 토큰 수를 알린다. 그 토큰은 template에 들어가고 페이지의 대화 상자에는 보이지 않으므로, 예시에 system을 직접 넣는다.
- 명령의 `scripts/…`는 이 SKILL.md가 있는 폴더 기준이다. `params.mjs`는 `--template`을 주지 않으면 그 폴더의 `assets/template.html`에서 계산 블록을 읽는다.
- Windows PowerShell 5.1은 인라인 JSON의 큰따옴표를 지운다. 그때는 `--template-kwargs`와 `--override`에 JSON 파일 경로를 넘긴다. `--expect`는 `total=1,235,814,400`처럼 쉼표 묶음도 받는다.
- 합친 모듈(GPT-2 `c_attn`, Phi-3 `qkv_proj`·`gate_up_proj`)은 페이지에서 논리 모듈(q·k·v, gate·up)로 나눠 그린다. 가중치 개수는 같다. 다만 PEFT로 합친 모듈에 LoRA를 붙이면 실제 학습 수가 논리 모듈별 셈보다 적다. `params.mjs`가 `주의:` 줄로 두 값을 함께 찍으니, 보고할 때 그 차이를 말한다.

### 2. 템플릿을 복사해 설정 채우기

- `assets/template.html`을 작업 폴더로 복사한다(예: `<work>/<slug>.html`). 스킬 폴더 안의 원본은 고치지 않는다.
- 스크립트 맨 위의 설정 블록(`MODEL`, `LORA`, `CONDS`, `EXAMPLE`, `TRAIN`, `RESULTS`)을 1단계 출력으로 바꾼다.
- `<title>`(두~네 낱말 이름)을 바꾼다. 머리말(`#eyebrow`, `#h1`)은 엔진이 설정에서 만들어 쓰므로 마크업을 고쳐도 덮어쓴다. 논문에 맞게 바꾸려면 `template-api.md` 1절의 두 줄을 고친다.
- 페이지에는 저자·지도교수·학교 이름을 넣지 않는다(사용자가 원할 때만).
- 항목의 뜻과 예시는 `references/template-api.md`에 있다.

### 3. 단계 글과 논문 고유 구간

- 기본 단계(전체 → 입력 → 토큰 → 임베딩 → 층 1 어텐션 → LoRA 확대 → 어텐션 뒤쪽 → MLP → 층 훑기 → 조건 → 출력 → softmax → 학습 손실 → 결과 → 마무리)는 계산값으로 글을 만든다. 숫자는 그대로 두고, 문장만 논문의 이야기에 맞게 고친다.
- 단계마다 출처 줄(`src`)을 단다: `공개 모델 구성(config.json)`, `논문 표 <번호>`, `이 예시를 따로 잰 값` 등. 기본 단계의 출처 줄은 설정으로 바꾼다: `EXAMPLE.src`(입력·토큰 단계, 기본 '새로 쓴 합성 예시'), `MODEL.expect.src`(전체 단계의 대조 출처, 기본 '공개된 합계'), `TRAIN.src`(학습 손실 단계).
- 평가처럼 논문에만 있는 구간은 템플릿의 그리기 기본 부품(`B(st).box/text/line/dots/unit`)으로 덧붙인다. 개수를 점으로 보여 줄 때는 점 하나 = 한 개다(count-true).
- 글 쓰는 법과 화면 규칙은 `references/visual-grammar.md`를 따른다.

### 4. 검증 — 스크린샷을 직접 본다

```bash
node scripts/make_tests.mjs <work>/<slug>.html <work>/test --ship <work>/<slug>_standalone.html
node scripts/shoot.mjs <work>/test --steps all --sizes 1600x900,520x900 --themes light,dark --sheet --perf all
```

- `make_tests.mjs`는 스크립트 문법을 검사하고(`node --check`), URL 인자로 테마·조건·단계를 고르는 시험용 사본과 독립 실행 사본을 만든다.
- `shoot.mjs`는 단계마다 헤드리스 Chrome으로 찍고, 3×3 모음 시트와 프레임 시간을 낸다. 전체 실행(기본 14단계 × 2크기 × 2테마 = 56장)은 기계 부하에 따라 1~20분이 걸리므로 백그라운드로 돌린다. 고친 뒤 몇 단계만 다시 볼 때는 `--steps lora,layers --conds 0,1`처럼 단계 key와 조건을 고른다. 같은 이름의 그림과 시트는 덮어쓰므로, 일부만 다시 찍은 뒤의 시트는 그 단계만 담는다.
- **시트를 전부 Read로 열어 본다.** 점검표와 헤드리스 함정(rAF가 거의 돌지 않음, 페이드 중간에 찍힘, 글꼴 늦게 로드)은 `references/verification.md`에 있다. 붉은 오류 띠(`#err`)가 보이면 합계가 틀렸거나 스크립트 오류다.

### 5. 게시

- Artifact 도구가 있으면 작업 파일(조각)을 그대로 게시한다. 새 게시면 `icon`을 주고, 고칠 때는 같은 파일 경로로 다시 게시한다. 다른 대화에서 고칠 때는 그 링크를 `url`로 넘기고, 먼저 읽는다.
- 링크는 기본이 비공개다. 공유는 사용자가 페이지의 Share 메뉴에서 한다.
- 독립 실행 사본은 4단계의 `--ship` 출력이다. 사용자가 원하는 폴더에 둔다.
- 공개 저장소나 공개 페이지로 낼 때는 미발표 연구의 수치와 개인 정보를 빼거나 가상값으로 바꾼다. 자세한 것은 `references/publishing.md`.

### 6. 보고

사용자에게 다음을 짧게 알린다.

- 링크와 독립 실행 사본의 경로.
- 무엇을 그렸는지: 층 수, 모듈, 얼린 값과 학습하는 값의 합계(공개 수치와 일치 여부).
- **무엇을 그리지 않았는지**: 가중치 파일이 없으면 행렬 안의 값 하나하나는 그리지 않았다는 것. 가중치를 주거나 다운로드를 허락하면 그때 추가할 수 있다고 제안한다.
- **실제 비율과 다르게 그린 것**: LoRA 띠의 두께(랭크는 모눈 한 칸보다 훨씬 작음), norm 판의 크기, 임베딩·LM head의 가로 길이(어휘 수만큼 길게 그리지 않음).
- 확인한 범위: 크기, 테마, 조건, 단계 수, 프레임 시간. 실제 브라우저에서 직접 눌러 보지 않았다면 그렇다고 말한다.

## 지킬 것

- **숫자**: 페이지의 모든 개수는 설정 블록에서 계산된 값이다. 결과 수치는 논문 표, 토큰 수는 실측이다. 출처 없는 숫자는 쓰지 않는다.
- **대신 쓰지 않기**: 다른 모델의 가중치를 대신 칠하지 않는다. 같은 계열의 작은 모델 값을 큰 모델 그림에 쓰는 것도 안 된다. 사용자가 시키지 않은 가중치 다운로드도 하지 않는다.
- **범위**: 템플릿은 디코더 전용·pre-norm 트랜스포머(Llama, Mistral, Qwen2, Gemma 1, Phi-3, GPT-2, TinyLlama 계열)를 바로 그린다. 인코더-디코더, post-norm(BERT), MoE, 비전 모델은 기본 부품으로 구간을 새로 짜되, 같은 문법(위→아래, 파랑 = 가중치, 실제 비율, LoRA는 오른쪽)을 지킨다. 계산 블록이 그 구조를 못 세면 `params.mjs --override`로 넣고 공개 합계로 대조한다.
  - Qwen3처럼 q·k norm이 있는 계열과 Gemma 2·3처럼 norm이 더 있는 계열은 `params.mjs`가 모르는 계열로 보고 멈춘다(exit 2). `--override`로 세면 그 norm 값이 빠지므로, 공개 합계와 얼마나 다른지 확인하고 보고에 적는다.
  - 조건마다 LoRA 대상 모듈이 다르면 설정만으로는 그릴 수 없다. `cond` 옵션으로 조건별 띠를 따로 그린다(`template-api.md` 2.3절, 6.3절).
- **외부 자원**: 페이지는 라이브러리 없이 돈다. 외부에서 불러오는 것은 Google Fonts 스타일시트 하나뿐이다.
- **이전 작업 재사용 금지**: 사용자가 참고 페이지를 주면 그 구조를 먼저 글로 적어 보고(무엇이 놓이고, 어떻게 배치되고, 무엇이 움직이는가) 거기에 모델을 얹는다.
