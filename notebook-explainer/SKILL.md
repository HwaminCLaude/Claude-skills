# Notebook Explainer

노트북/코드를 **단일 HTML 학습 페이지**로 바꾼다. 문서가 아니라 *수업*이다 —
모든 코드 줄이 클릭되어 스스로를 설명하고, **모양이 바뀌는 곳마다 시각화가 붙는다.**

`references/` 의 레시피는 전부 **실제로 동작한 페이지에서 역추출**한 것이다.
이미 이 스킬로 만든 `*_인터랙티브_해설.html` 이 로컬에 있다면, 새로 쓰기 전에 하나 열어
구조를 먼저 볼 것 — 코드 카드 형식·위젯 배치·배지 사용법이 그대로 보인다.
없어도 아래 절차만 따르면 된다.

---

## 1. 소스 읽기

| 입력 | 방법 |
|---|---|
| `.ipynb` | `PYTHONUTF8=1 PYTHONIOENCODING=utf-8 python scripts/extract_notebook.py "<경로>"` |
| `.py` / `.js` / 기타 | **`Read` 도구로 직접 읽는다** (추출 스크립트를 거치지 말 것) |

`.ipynb` 를 절대 그대로 읽지 말 것. 실측상 노트북의 최대 97%가 base64 이미지다
(`Step0_EDA.ipynb` = 3766KB 중 3649KB). 추출 스크립트는 소스를 무손실로 두고 출력만
요약해 40배 이상 줄이며, ANSI 색상 코드를 벗기고 `shape_hints` 를 따로 모아 준다.

### 대용량 게이트 — 먼저 확인한다

추출 결과의 **`stats.gate_exceeded` 가 `true` 면 통째로 만들지 않는다.**
장 목록을 뽑아 `AskUserQuestion` 으로 "어느 장부터 어느 장까지 만들까요?"를 먼저 묻고,
선택 범위만 해설한다. 사용자에게는 `stats.gate_reasons` 를 그대로 근거로 보여준다.

임계값은 `scripts/extract_notebook.py` 상단 상수가 유일한 기준이다
(현재 값은 `stats.gate_rule` 에 문자열로 실려 온다). 여기 프로즈에 숫자를 복사해 두지 말 것 —
반드시 어긋난다.

게이트가 없으면 완성하지 못할 페이지를 조용히 쓰기 시작하게 된다.
시각화를 전부 붙이므로 셀당 분량이 크다 — 임계값은 여유가 아니라 **상한**이다.

## 2. Shape·구조 분석 패스 (ML 코드일 때)

소스에 `nn.Module` · `Sequential` · `Model(` · `Conv` · `LSTM`/`GRU` · `Embedding` ·
`model.summary()` · `.reshape(` · `.view(` 중 하나라도 있으면 **ML 코드로 판별**하고,
`references/architecture-recipes.md` 를 읽은 뒤 다음을 뽑아낸다:

1. **데이터 흐름** — 원본에서 모델 입력까지 거치는 단계와 각 시점의 모양
2. **레이어별 텐서 shape** — 입력→출력, 파라미터 수, 왜 그 크기가 나왔는지 계산식
3. **전처리 변환 체인** — 구체적 샘플 하나가 단계마다 어떻게 바뀌는지
4. **함수 호출 관계** — 직접 정의한 함수가 3개 이상일 때만

(선택) `code-analysis-ppt-generator` 스킬이 함께 설치돼 있다면 그 `ANALYSIS_TEMPLATE.md` 의
프레임워크 [2][3][4][6]이 같은 내용을 정적 표로 정리해 둔 것이라 도움이 된다. 없어도 무방하다.

### Shape 출처 규칙 — 지어내지 않는다

HTML은 정적이라 PyTorch/TF를 돌릴 수 없다. 값은 **작성 시점에 확정해 박아 넣는다**(하드코딩).
단 출처를 구분한다:

- **관측값** — 출력에 실제로 찍힌 것 (`print(x.shape)`, `model.summary()` 표) → 그대로 표기
- **추정값** — 코드에서 계산한 것 → `추정` 배지를 단다
- **기호** — 런타임 결정 (`None`, 배치 크기) → `B` 같은 기호로 두고 기호임을 밝힌다

`model.summary()` 가 있으면 그 표가 정답이다. 없으면 그 모델의 모양은 **전부 추정**이고,
해당 셀에 그 사실을 명시한다. 자세한 체크리스트는 `architecture-recipes.md` 8절.

## 3. 시각화 인벤토리 — HTML 쓰기 전에 반드시

**위젯 개수 상한은 없다.** shape이 바뀌는 곳, 구조가 있는 곳, 데이터가 흐르는 곳에는
예외 없이 시각화를 붙인다. 시각화할 게 없는 셀(import, 시드 고정)만 생략한다.

코드를 읽은 직후, 페이지를 쓰기 전에 이 표를 먼저 만든다:

| # | 셀 | 무엇이 바뀌나 / 무슨 구조인가 | 근거 shape | 출처 | 쓸 위젯 |
|---|---|---|---|---|---|
| 1 | cell 4 | 28×28을 784로 폄 | (60000,28,28)→(60000,784) | 관측 | R9 변환 체인 |
| 2 | cell 5 | MLP 3층 | 784→256→256→10 | 관측(summary) | R6 + R7 |

표에 오른 항목은 **전부** HTML에 대응 시각화가 있어야 한다. 마지막에 대조한다.
누락 방지 장치이므로 건너뛰지 말 것.

## 4. 페이지 설계

- **언어** — 사용자 언어에 맞춘다.
- **의미색** — 주제에서 뜻을 끌어온 색 4~6개. ML이면 차원의 종류
  (공간=주황 / 특징=파랑 / 클래스=초록 / 배치=회색)가 검증된 조합이다.
  이 색이 있으면 "MLP는 즉시 주황→파랑, CNN은 Flatten까지 주황 유지"가 그림만으로 전달된다.
  히어로에 범례 필수. 흔한 AI 기본값(크림+테라코타 세리프, 검정+형광 초록)은 피한다.
- **글꼴** — 한국어면 `IBM Plex Sans KR` + 코드용 `JetBrains Mono` (Google Fonts만 허용).
- **시그니처 위젯** — 맨 위에 하나. 30초 만에 노트북의 핵심을 잡게 하는 것.
  대담함은 여기에 몰아 쓰고 나머지는 절제한다.

## 5. 페이지 구성

1. **스티키 네비** — 장 chip 링크 (섹션에 `scroll-margin-top`)
2. **히어로** — 제목, 2~3문장 요약, 의미색 범례, 시그니처 위젯
3. **데이터 흐름 파이프라인(R8)** + **목차** — 셀마다 한 줄 역할
4. **코드 셀마다 한 섹션** (스크립트면 논리 블록마다):
   - 셀 태그 + 제목 + **왜 이 셀이 이 흐름에 있는지** (무엇을 하는지가 아니라)
   - 어두운 코드 카드 — **의미 있는 모든 줄이 클릭 가능**. 설명은 문법 재진술이 아니라
     의도와 결과를 가르친다 ("`synchronize()` 없으면 측정값이 거짓말을 한다")
   - 키포인트 chip 2~3개
   - 인벤토리에 오른 시각화
   - 소스에 문제가 있으면 정직하게 배너로 드러낸다 (죽은 코드, 시드 없음, 오타, 실패한 호출)
5. **푸터** — 전체 흐름 한 줄 요약 + 배지 범례 + 생략한 것(예: 함수가 없어 호출 그래프 생략)

### 지켜야 할 규칙

- 원본의 교육 설계를 보존한다. `<details>` 로 답을 숨겼으면 경고문까지 그대로 접어 둔다.
- 긴 줄은 `...` 로 줄여 표시해도 되지만, 생략한 내용도 설명에는 담는다.
- 줄 설명은 `data-n` 속성에. 카드 전체를 핸들러 하나로 묶는다.
- **외부 JS 라이브러리 금지.** 손으로 쓴 vanilla JS와 인라인 SVG만. Google Fonts만 예외.
- `data-n` 은 `innerHTML` 로 들어간다 — 설명에 날 `<` `>` 를 넣지 말 것.
- ~380px까지 반응형, `prefers-reduced-motion` 존중, 가로 스크롤 금지
  (넓은 요소는 `overflow-x:auto` 로 감싼다).

## 6. 검증

```bash
# 최초 1회만: npm i -g playwright && npx playwright install chromium-headless-shell
python -m http.server 8899 --bind 127.0.0.1        # file:// 은 브라우저 제약이 있다
node scripts/verify_page.js http://127.0.0.1:8899/<파일>.html \
     --expect "269,322|(None, 288)|98.99"
```

통과 기준: `verdict: PASS` — 콘솔 에러 0, 가로 스크롤 없음, 줄 클릭이 패널을 채움,
`--expect` 로 넘긴 관측값이 전부 페이지에 존재. ML 페이지면 `viz2code` / `code2viz` 의
`rowHighlighted`·`svgBlockHighlighted` 가 모두 true.

정적 검사로는 "클릭이 정말 동작하는가"를 증명할 수 없으므로 이 단계를 건너뛰지 말 것.

## 7. 전달

```
저장: <원본과 같은 폴더>/<원본이름>_인터랙티브_해설.html
알림: 저장한 절대경로를 채팅에 그대로 출력
```

Artifact로 발행하지 않는다. 채팅 답변에는 사용법(줄 클릭, 위젯별 한 줄)과
**소스에서 발견한 문제**를 간단히 적는다. 긴 마무리 말은 붙이지 않는다.

### 폴더 일괄 모드

인자가 폴더면 하위 `.ipynb` 를 순회한다(`.ipynb_checkpoints` 제외).
**일괄 모드에서는 게이트가 묻지 않고 건너뛴다** — 실행 중 15번 물을 수 없기 때문이다.
건너뛴 파일은 마지막에 "커서 개별 실행이 필요합니다" 목록으로 모아 보고한다.
대화형 질문은 단일 파일 모드 전용이다.

## 위젯 고르기

범용 5종은 `references/widget-recipes.md`, ML 전용 5종은 `references/architecture-recipes.md`.

| 코드에 있는 것 | 위젯 |
|---|---|
| 내부 관계가 있는 자료구조 (행렬, 트리, 인덱싱) | **클릭 하이라이트 시각화** — 출력 칸을 누르면 입력이 켜지고 식이 뜬다 |
| 상태가 변하는 반복문·알고리즘 | **스텝 애니메이터** — 재생/한 스텝/리셋, 변수 실시간 표시 |
| 임계값 판단 공식 (`x > y + z`) | **슬라이더 계산기** — 입력마다 슬라이더, 막대와 판정 |
| 분기 (try/except, if 사슬) | **분기 시뮬레이터** — 시나리오 버튼, 실제 콘솔 출력 재현 |
| 규모에 따라 달라지는 트레이드오프 | **파라미터 스윕** — 슬라이더 하나 + 결과 카운터 |
| **층마다 텐서 모양이 바뀜** | **R6 Shape 추적기** — 입력→출력→파라미터 표, 클릭 시 코드 줄 연동 |
| **모델 구조** | **R7 블록 다이어그램** — 인라인 SVG, 화살표마다 shape 라벨 |
| **원본에서 모델 입력까지의 단계** | **R8 데이터 흐름 파이프라인** |
| **전처리가 여러 변환을 몰아서 함** | **R9 변환 체인 스테퍼** — 샘플 하나를 단계별로 |
| **직접 정의한 함수 3개 이상** | **R10 호출 관계 그래프** |

어디에도 안 맞으면 억지 위젯보다 산문 + 정적 다이어그램이 낫다.

**R6와 R7은 반드시 같은 데이터 배열에서 그린다** — 따로 쓰면 층을 고칠 때 한쪽만 고치게 된다.
구현은 `architecture-recipes.md` 1절.
