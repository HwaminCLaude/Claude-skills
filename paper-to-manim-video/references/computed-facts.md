# 계산 노드 — 화면의 숫자를 계산에서만 가져오기

논문·연구 영상은 수치를 말한다. 상관계수, 적합도, p값. 그 숫자가 **계산 결과가 아니라 그럴듯한
자릿수**이면 영상 전체가 무너진다. 이 문서는 그 일이 일어나지 않게 하는 규약이다.

**한 문장 규약**: `analysis/`가 계산하고, `facts.json`이 기록하고, 씬은 `facts.json`에서만 읽는다.
손으로 옮겨 적는 경로는 없다.

---

## 1. 배치

```
<project-root>\
├─ analysis\
│  ├─ <도메인>.py        # 계산 본체 — 영상에서 이 코드를 그대로 보여줄 수 있게 쓴다
│  ├─ run_analysis.py    # 전부 실행하고 facts.json을 쓴다
│  ├─ data\*_deid.csv    # 비식별 작업 사본
│  └─ facts.json         # ★ 영상이 읽는 유일한 숫자 출처
└─ ep01_…\ ep02_…\
```

```bash
python scripts/compute_facts.py --root <project>          # 실행 + 검증
python scripts/compute_facts.py --root <project> --check  # 검증만
```

`facts.json` 최상위 키 세 개는 필수다:

| 키 | 용도 |
|---|---|
| `source` | 어떤 데이터인지 한 줄. 영상에 표시한다 |
| `criteria` | 논문·계획서가 정한 **판정 기준**. 계산값과 분리해 둔다 |
| `invariants` | `{검증이름: bool}`. 하나라도 false면 러너가 실패한다 |

## 2. 씬에서 읽는 법

```python
import json
from pathlib import Path as _Path

FACTS = json.loads((_Path(__file__).parent.parent / "analysis" / "facts.json")
                   .read_text(encoding="utf-8"))

kmo = FACTS["efa"]["kmo"]
label = mono(f"KMO = {kmo:.3f}", font_size=28)
```

**하드코딩 금지.** `kr("KMO = .922")` 라고 쓰는 순간 분석을 다시 돌려도 영상이 안 바뀐다.
반올림 자릿수도 `facts.json`을 따른다 — 영상에서 `.92`, 논문에서 `.922`가 되면 안 된다.

## 3. 기준값과 계산값을 눈으로 구분한다

시청자는 "이 숫자가 데이터에서 나온 건가, 연구자가 정한 건가"를 즉시 알아야 한다.

| 종류 | 표현 |
|---|---|
| **기준값** (고유값 ≥ 1.0, 적재 ≥ .40, α ≥ .70) | 회색 점선, 캡션에 출처 표기 |
| **계산값** (실제 KMO·χ²·적재값) | 강조색, 굵게 |

기준의 출처가 원문에 없으면 **통용 기준임을 화면에 밝힌다**. 논문이 말한 것처럼 보이게 하지 않는다.

## 4. 불변량 — 검산이자 교육 내용

라이브러리 없이도 정확성을 확보하는 방법이자, 그 자체로 좋은 장면이 된다.

| 불변량 | 무엇을 잡아내나 |
|---|---|
| `Σλᵢ = p` | 상관행렬 고유분해가 제대로 됐는가 |
| **회전 전후 공통성 불변** | 회전이 무엇을 바꾸고 무엇을 안 바꾸는가 — 그대로 하이라이트 장면 |
| `RᵀR = I` | 직교회전의 정의 |
| `χ² = (N−1)·F_ML` | ML 추정이 수렴했는가 |
| α를 공분산 항등식으로 재계산 | 공식 구현 오류 |
| 기존 결과 재현 | 연구자가 이미 내린 판단(예: CITC 탈락 문항)을 코드가 복원하는가 |

마지막 항목이 가장 강력하다. 실제 사례: 초기 40문항의 CITC를 직접 계산했더니 `.30` 미만이 하나뿐이었고,
그게 연구자가 실제로 뺀 문항과 일치했다. 코드가 맞다는 증거이자 영상의 실증 장면이 됐다.

## 5. 라이브러리보다 직접 구현

`factor_analyzer.analyze()` 한 줄은 정답을 주지만 아무것도 가르치지 못한다. 화면의 수식과 코드가
1:1이어야 한다. `numpy`+`scipy`로 쓴 15줄짜리 varimax는 화면에 올릴 수 있지만 라이브러리 호출은 못 올린다.

라이브러리는 **교차검증용 보조**로만 쓴다. `factor_analyzer`·`semopy`는 sdist만 배포돼 설치가 실패할 수
있으므로 **필수 의존성으로 두지 않는다.** 실패해도 불변량으로 정확성이 확보되면 파이프라인을 진행한다.

## 6. 개인정보

연구 데이터에는 식별정보가 들어 있을 수 있다 — 실제로 겪었다. 응답자 222명의 **실명**이 컬럼 하나에
그대로 있었다.

- **원본은 읽기만 한다.** 수정·삭제하지 않는다
- `analysis/deid.py`로 **비식별 사본**을 만들고 그 뒤로는 사본만 쓴다
- 자유응답 컬럼(부서명, 사용 기기 등)도 소규모 집단에서는 식별 가능하다 — 함께 뺀다
- 비식별 후 **잔여 실명 검사**를 자동으로 돌린다 (한글 2~4자 패턴)
- 커밋·납품 전에 `facts.json`·`shots.json`·`script.md`·`main.py`·프레임을 정규식으로 다시 훑는다

## 7. 결과표 3장면 세트

수치를 다루는 영상은 "이 값이 얼마인가"만으로 부족하다. 시청자는 **자기 출력창에서 그 값을 찾아야** 한다.
분석 단계마다 세 장면을 세트로 만든다.

1. **계산** — 무슨 수식이 돌았는가
2. **출력창** — SPSS/AMOS가 실제로 뱉는 표를 재현. 표 이름·칼럼명은 **영문 원문 그대로**
   (`KMO and Bartlett's Test`, `Total Variance Explained`, `Rotated Component Matrix`,
   `Item-Total Statistics`, `Reliability Statistics`, `Model Fit Summary`).
   **어느 칸을 봐야 하는지 화살표로 짚고, 흔히 잘못 보는 칸도 짚는다**
3. **논문 Table** — 학술지 표로 옮기면 어떤 모양인지, 무엇을 빼고 무엇을 남기는지

표는 `Table`/`DecimalTable` 대신 `VGroup` + `arrange_in_grid`로 직접 만든다(폰트 제어 때문).
셀은 `mono(f"{v:.2f}", font_size=18)` — `mono()`는 ASCII 전용이라 한글을 넣으면 두부가 된다.

## 8. 데이터가 기대와 다를 때

선행연구가 4요인인데 데이터가 6요인을 내놓을 수 있다. **데이터가 말하는 대로 보여준다.**
요인 수를 미리 정해 놓고 맞추지 않는다. 차이가 나면 그 차이 자체가 좋은 내용이다.

기준에 따라 답이 갈리는 경우(고유값 ≥1은 6요인, 스크리 도표는 3요인)도 **둘 다 보여주고
"기준을 무엇으로 잡느냐에 따라 달라진다"는 것을 가르친다.** 하나만 보여주고 확정된 것처럼 말하지 않는다.

경계에 걸친 값도 숨기지 않는다. 적재 `.398`과 `.400`은 반올림 한 자리로 판정이 뒤집힌다 —
그런 문항 목록을 `facts.json`에 따로 담아 화면에 올린다.
