# 화면 검수 — 렌더가 성공해도 화면은 틀릴 수 있다

`verify_output.py`는 **길이와 해상도**를 본다. 그것만 통과하고 화면이 틀린 결함이
실제 두 시리즈(38구간 + 41구간)에서 **19건** 나왔다. 전부 완성본에 들어간 뒤에 발견했다.

공통점: **예외도, 경고도, 길이 오차도 없다.** 눈으로 보기 전에는 알 방법이 없다.

이 문서는 그 19건을 두 갈래로 나눠 각각의 방어선을 정한다.

| 갈래 | 성격 | 방어선 |
|---|---|---|
| A. 조용히 틀리는 코드 | 특정 API 조합이 항상 틀린다 | **정적 린트** (`lint_scenes.py`) |
| B. 자리 잡기 | 화면에 이미 있는 것과 부딪힌다 | **프레임 스윕** (`sweep_frames.py`) + 눈 |

## 1. Stage 5.5 — 렌더 전 정적 린트

```bash
python scripts/lint_scenes.py --root C:/manimwork/<slug>
```

ERROR가 하나라도 있으면 렌더하지 말고 먼저 고친다. 규칙 11종:

| 규칙 | 무엇을 잡나 | 왜 조용히 틀리나 |
|---|---|---|
| `mono-hangul` | 고정폭 헬퍼에 한글 | 글립이 없어 **두부(□)**. 예외는 안 난다 |
| `emoji` | 🔍 🔒 ⚡ 같은 이모지 | 점이 하나도 없는 mobject가 되어 `move_to`가 무효화되고, `next_to`로 붙인 **이웃까지 원점으로 끌려간다** |
| `latex-hangul` | `MathTex`/`RaeTex` 안 한글 | LaTeX 유니코드 오류 (이건 시끄럽게 죽는다) |
| `arc-fill` | `Line(path_arc=…).set_opacity()` | `set_opacity`가 **면까지** 칠해 호가 흰 덩어리가 된다 |
| `vgroup-image` | `VGroup`에 `ImageMobject` | `VGroup`은 이미지를 담지 못한다 → `Group` |
| `surrounding-rect` | raenim `SurroundingRect(대상)` | manim `SurroundingRectangle`과 **다른 클래스**다 |
| `fadein-plus-indicate` | 같은 `playw`에 등장 + `Indicate` | 등장이 취소돼 **값이 사라진다** |
| `fadein-plus-animate` | 같은 `playw`에 등장 + `.animate` (WARN) | 끝 상태는 맞지만 등장 연출이 없어진다 |
| `inline-highlight-rect` | `playw(Create(row_box(tab, 2)))` 처럼 강조 사각형을 인라인 생성 (WARN) | 변수가 없어 **지울 수 없다**. 표를 지워도 빈 사각형만 남는다 |
| `highlight-leftover` | `highlight()`의 `disappear` 미재생 | 코드가 사라진 뒤 **빨간 강조 글자만 남는다** |
| `hardcoded-timing` | `run_time=`을 코드에 적음 (WARN) | 대본을 고쳐도 영상이 안 따라온다 |

린터가 없는 규칙(`VGroup.scale()`이 흩어진 점의 위치를 벌린다 등)은
`references/troubleshooting.md`의 함정 목록을 본다.

## 2. Stage 8 — 본번 렌더 뒤 프레임 스윕

```bash
python scripts/sweep_frames.py --root C:/manimwork/<slug> --quality qh
```

기본 3지점: **35% · 70% · 마지막(끝−0.6초)**. 각 지점이 잡는 것이 다르다.

| 지점 | 무엇이 보이나 |
|---|---|
| 35% | 요소가 절반쯤 쌓인 상태. 새로 들어온 블록이 기존 것과 부딪히는 순간 |
| 70% | 가장 붐비는 순간. 겹침이 여기서 제일 잘 드러난다 |
| 마지막 | **사라졌어야 하는데 남은 것**. 강조 찌꺼기, 클리어 누락 |

41구간이면 123장이다. 많아 보이지만 이걸 건너뛰면 B그룹은 **한 건도 못 잡는다.**

### 볼 때 찾는 것

1. **글자 겹침** — 두 텍스트가 같은 자리에 또렷하게 포개짐 (가장 중요)
2. **화면 밖 잘림** — 프레임 경계에서 잘림
3. **남은 찌꺼기** — 사라졌어야 할 강조색 글자·박스가 홀로 떠 있음
4. **두부(□)** — 한글 폰트 실패
5. **가림** — 도형·논문 그림 위에 라벨이 올라타 안 읽힘

### 결함이 아닌 것 (보고하지 말 것)

- **페이드/Transform 전환 중** 두 요소가 반투명하게 겹쳐 보이는 것. 샷 타임라인
  (`shots.json`의 `run_time`)을 보고 그 순간이 전환 구간인지 확인한다. 전환이면 정상이다.
- 검은 배경에 요소가 적어 비어 보이는 것
- 화면 아래 회색 캡션(출처 표기)

### 시각 모델에 맡길 때

서브에이전트에게 시켜도 되지만 **결과 텍스트가 비어 돌아오는 경우가 있다.**
그럴 때는 미루지 말고 직접 `Read`로 본다. 한 번에 6~8장씩 묶으면 빠르다.

### 스윕도 새는 곳이 있다 — 린트와 함께 써야 한다

96장을 다 본 편에서도 **구간 앞부분의 찌꺼기 하나를 놓쳤다.**
35% 지점에서는 아직 지워지기 전이라 정상으로 보이고, 70%·마지막 지점에서는
그 구간이 이미 다른 화면으로 넘어가 있어서 눈에 안 띈 것이다.
`inline-highlight-rect` 린트 규칙이 나중에 그 자리를 정확히 집어냈다.

→ **스윕은 배치를, 린트는 수명을 본다.** 둘 다 돌린다.
스윕에서 아무것도 안 나왔다고 린트 WARN을 넘기지 않는다.

## 3. 자리 잡기 전에 재는 습관

프레임은 **x ∈ [−7.11, 7.11], y ∈ [−4, 4]** 이다. 배치하기 전에
"이미 화면에 있는 것이 어디까지 차 있나"를 먼저 센다.

```python
# 나쁨 — 기준물이 좁으면 라벨 절반이 화면 밖으로 나간다
o1 = MathTex("O(1)").to_corner(UL, buff=0.7)
o1_l = kr("1편에서 말한 경로 길이", font_size=17).next_to(o1, DOWN, buff=0.2)

# 좋음 — 왼쪽에 맞추고, 그래도 길면 줄을 접는다
o1_l = kr("1편에서 말한\n경로 길이", font_size=17)
o1_l.next_to(o1, DOWN, buff=0.2).align_to(o1, LEFT)
```

자주 쓰는 안전 자리와 관용구는 `references/scene-templates.md`에 있다.

### 숫자 표가 화면의 주인공일 때 (손계산 워크스루)

표와 계산 줄만으로 채우는 편에서는 자리 다툼이 유난히 잦다. 다음 셋을 지킨다.

- **표의 윗변 y를 먼저 계산하고** 계산 줄은 그 위에서만 논다.
  4행짜리 표(`cell_h=0.56`)를 `DOWN*1.5`에 두면 윗변이 대략 y = −0.05다.
- 계산 줄 두 벌을 동시에 띄우려면 **1.1 이상** 떼어 놓는다(`UP*2.2`와 `UP*1.05`).
- 막대 이름표는 **막대·값라벨을 통틀어 가장 아래**보다 더 아래에 둔다.
  0선 바로 아래에 고정하면 음수 막대의 값 라벨과 겹친다.
- 구간 제목(`scene_title`)과 본문 제목에 **같은 문구**를 쓰지 않는다 — 화면에 두 번 뜬다.
  화면 위쪽에 캡션을 둘 일이 있으면 구간 제목을 먼저 `FadeOut` 한다.

## 4. CP3에 올릴 것

- **생성 이미지를 쓴 컷 전부** (0개면 0개라고 명시한다)
- **REWORK 판정 구간** (길이 오차 15% 초과)
- **논문 수치를 인용한 컷** — 사용자가 논문과 직접 대조할 수 있게 png로 뽑아 보낸다
- **스윕에서 고친 결함 목록** — 몇 장 봤고 몇 건 고쳤는지

납품 폴더에 검수 프레임을 넣을 때는 **재렌더 이후에 다시 뽑는다.**
수정 전 프레임이 남아 있으면 검수 폴더가 영상과 어긋난다.
