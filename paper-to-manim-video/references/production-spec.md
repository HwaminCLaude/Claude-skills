# 제작 사양 — CP0에서 사용자와 정하는 것

Stage 1(파싱)이 끝나면 **바로 대본을 쓰지 않는다.** 먼저 사용자에게 네 가지를 묻는다.
같은 논문이라도 답에 따라 완전히 다른 영상이 나오고, 나중에 바꾸면 대본부터 다시 써야 한다.

`AskUserQuestion` **한 번**에 네 문항을 함께 올린다. 각 문항에는 "직접 지정"이 자동으로
붙으므로(Other), 사용자가 원하는 방식을 자유롭게 적을 수 있다.

## 설치별 확정 기본값

**한 번 정해진 문항은 다시 묻지 않는다.** 사용자가 답한 값을 아래 표에 적어두면
그 문항은 CP0에서 빠지고 `spec.json`에 자동으로 채워진다. 매번 같은 걸 네 번 묻는 것은
인터랙티브가 아니라 성가심이다.

| 문항 | 확정값 | 물어볼까 |
|---|---|---|
| 편성 | — | **매번 묻는다** (논문마다 분량이 달라 그때그때 고르겠다고 함) |
| 실습 | 노트북 3권 | 안 묻는다 |
| 나레이션 | 음성 + 자막 트랙 | 안 묻는다 |
| 검수 | 표준 (린트 + 구간당 3프레임 스윕 + 눈으로) | 안 묻는다 |

*(스킬을 새로 받았다면 이 표를 비우고 네 문항을 다 묻는다. 답을 받으면 여기에 적는다.)*

그래서 지금 CP0은 **편성 한 문항**만 올린다. 나머지 셋은 기본값으로 채우고
편성안을 제시할 때 한 줄로 알린다 — "노트북 3권 · 음성+자막 트랙 · 표준 검수로 갑니다.
바꾸시려면 말씀해주세요."

사용자가 다른 방식을 말하면 그 말이 우선이고, 반복해서 다른 값을 고르면 이 표를 갱신한다.

## 문항 1 — 편성 템플릿

`header: "편성"` / 논문과 코드의 분량을 보고 **권장안을 첫 번째**에 둔다.

| 템플릿 | 편수 | 총 길이 | 뼈대 | 이럴 때 |
|---|---|---|---|---|
| `series-5` **표준** | 5편 | 30~35분 | 문제 → 핵심 기법 → 나머지 부품 → 결과·한계 → 코드 대조 | 논문 + 코드가 둘 다 있고 제대로 다룰 때 |
| `series-3` **압축** | 3편 | 18~21분 | 문제+기법 → 결과 → 코드 | 코드가 작거나 논문이 짧을 때 |
| `single` **단편** | 1편 | 6~8분 | 한 아이디어만 | "이 개념만 짧게" |
| `code-first` **코드 중심** | 4편 | 24~30분 | 코드 구조 → 핵심 함수 → 논문 대조 → 돌려보기 | 코드가 주인공일 때 |
| `results-first` **결과 중심** | 3편 | 18~22분 | 무엇이 좋아졌나 → 왜 되나 → 한계 | 재현·벤치마크가 목적일 때 |

**위 표를 문서에서 읽지 말고 스크립트로 뽑는다** — 템플릿이 늘어나도 문서를 고칠 필요가 없다:

```bash
python scripts/list_templates.py --json     # AskUserQuestion의 options 형태
python scripts/list_templates.py            # 사람이 읽는 표
```

각 템플릿의 편별 뼈대도 같은 JSON에 있다. 그대로 쓰지 말고
**논문의 실제 절 구성에 맞춰 제목과 구간을 다시 짠다.** 템플릿은 편수와 흐름의 출발점이다.

### 템플릿을 새로 추가하려면

`assets/series_templates.local.json`에 같은 형식으로 넣는다.
이 파일은 **스킬을 업데이트해도 지워지지 않고**, 선택지에 자동으로 뜬다(목록에서 `+`로 표시).
같은 키를 쓰면 기본 템플릿을 덮어쓴다.

```json
{
  "series-2": {
    "label": "2편 초압축",
    "recommended_for": "발표 전 빠르게",
    "total_minutes": "12~14",
    "episodes": [
      {"slug": "ep01_idea",  "role": "아이디어", "asks": "무엇을 어떻게 풀었나",
       "sources": "서론 + 핵심 절", "scenes": "6~8"},
      {"slug": "ep02_proof", "role": "근거",     "asks": "왜 믿을 만한가",
       "sources": "실험 절, 결과 표", "scenes": "6~8"}
    ]
  }
}
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `label` | ✔ | 선택지에 뜨는 이름 (짧게) |
| `episodes[]` | ✔ | 편 목록 |
| `episodes[].slug` | ✔ | 폴더 이름 (`ep01_xxx`) |
| `episodes[].role` | ✔ | 그 편의 역할 — 선택지 설명의 뼈대(`A → B → C`)가 된다 |
| `episodes[].asks` | ✔ | 그 편이 답하는 질문 한 줄 |
| `episodes[].sources` | | 논문·코드의 어느 부분을 쓰나 |
| `episodes[].scenes` | | 구간 수 범위 |
| `recommended_for` | | 언제 이걸 고르나 |
| `total_minutes` | | 총 길이 |

넣은 뒤 `python scripts/list_templates.py --check`로 스키마를 확인한다.

## 문항 2 — 실습 자료

`header: "실습"`

| 선택 | 산출물 |
|---|---|
| **노트북 3권** (권장) | 해부 + 밑바닥 구현 + 학습 실습. 코랩에서 바로 실행 |
| 노트북 1권 | 핵심만 한 권 |
| 없음 | 영상만 |

노트북을 만들면 `notebooks/build_notebooks.py`가 **원본**이고 `.ipynb`는 생성물이다.
첫 셀이 저장소를 `git clone` 하게 해서 사용자가 준비할 것이 없게 만든다.

## 문항 3 — 나레이션

`header: "나레이션"`

| 선택 | 결과 |
|---|---|
| **음성 + 자막 트랙** (권장) | edge-tts 합성 + `narration.srt`를 트랙으로. 유튜브가 자동 인식 |
| 음성 + 태운 자막 | `mux_av.py --burn`. 화면에 자막이 박힌다 |
| 자막만 (직접 녹음) | `script.md` + `narration.srt`만. `tts_narrate.py`는 건너뛴다 |

어느 쪽이든 `script.md`는 항상 만든다 — 사용자가 직접 읽으면 영상 길이와 맞는다.

## 문항 4 — 검수 강도

`header: "검수"`

| 선택 | 하는 일 | 비용 |
|---|---|---|
| **표준** (권장) | 린트 + 구간당 3프레임(35/70/끝) 스윕 + 눈으로 확인 | 41구간 → 123장 |
| 정밀 | 표준 + 구간당 5프레임 + 대본 사실검증 다중 에이전트 | 2배 |
| 빠름 | 린트 + 길이 검증만 | 프레임 안 봄 |

**"빠름"을 고르면 자리 겹침·화면 밖 잘림은 못 잡는다**는 것을 그대로 말해준다.
실제로 두 시리즈에서 그런 결함이 19건 나왔고 전부 눈으로만 잡혔다.

## 답을 받은 뒤

1. 답을 `<root>/spec.json`에 적어둔다 — 나중 단계가 여기서 읽는다.

```json
{
  "series": "series-5",
  "episodes": 5,
  "notebooks": 3,
  "narration": "tts+srt",
  "qa": "standard",
  "notes": "사용자가 직접 적은 요구사항이 있으면 그대로"
}
```

2. 편성안(편별 제목·구간·다루는 절)을 만들어 **CP1 승인**을 받는다.
   이때는 표가 가장 읽기 쉽다:

```
| 편 | 제목 | 길이 | 구간 | 다루는 것 |
```

3. 사용자가 "직접 지정"으로 다른 방식을 적었으면 **그 말을 그대로 따른다.**
   템플릿은 기본값이지 제약이 아니다.

## 사양이 뒤 단계에 미치는 영향

| spec 키 | 영향 |
|---|---|
| `series` / `episodes` | Stage 2 편성, 편별 길이 상한(5~8분), 구간 수(4~11) |
| `notebooks` | Stage 4에서 `notebooks/build_notebooks.py` 작성 여부 |
| `narration` | Stage 7에서 `tts_narrate.py` 실행 여부, `mux_av.py --burn` 여부 |
| `qa` | Stage 5.5 린트(항상), Stage 8 스윕 지점 수, 사실검증 실행 여부 |
