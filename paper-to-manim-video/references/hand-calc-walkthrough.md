# 손계산 워크스루 — 예시 숫자가 모델을 통째로 지나가게 만들기

`walkthrough-6` 편성을 고른 경우에만 읽는다.

만들려는 것: **시청자가 계산기를 들고 화면의 숫자를 따라 계산해도 끝까지 값이 맞는** 시리즈.
구조를 설명하는 영상이 아니라, 예시 데이터 한 벌이 모델 내부를 지나가는 과정을 전부 보여준다.

Transformer(arXiv:1706.03762)로 한 번 완주했다(6~11편, 47분 50초). 아래는 그때 실제로
막혔던 것들과 해법이다. 다른 논문에 옮길 때도 **1·2·3번은 거의 그대로 적용된다.**

---

## 0. 세 박자를 반복한다

매 단계 이렇게 간다. 이 리듬이 무너지면 시청자가 따라오지 못한다.

1. **수식 정의를 먼저 적는다** — `MathTex`로, 한글 없이
2. **숫자를 대입한다** — `mono`로 한 줄씩, 곱셈 하나가 한 줄
3. **결과를 확인한다** — 표의 한 칸이 채워지거나 벡터가 완성된다

나레이션도 같은 순서다. "정의는 이렇습니다 → 넣어 봅시다 → 그래서 …이 됩니다."

## 1. 장난감 크기 고르기

가장 중요한 결정이다. 잘못 고르면 손계산이 불가능해지거나 예시가 깨진다.

| 규칙 | 이유 |
|---|---|
| **제곱근이 정수가 되는 차원**을 고른다 (d=4 → √4=2) | 임베딩 스케일링이 "×2"가 되어 암산이 된다. d=6이면 2.449라 매 줄이 지저분해진다 |
| 내적하는 축은 **2개**로 (d_k=2) | 곱셈 두 번 + 덧셈 한 번이면 끝난다. 4개가 되면 화면과 인내심이 같이 무너진다 |
| 층은 **1개** | "논문은 N=6, 여기선 1"이라고 화면에서 밝힌다 |
| 어휘는 **5~7개** | 확률 막대가 화면에 다 들어가고, 오답 후보를 한둘 섞을 수 있다 |
| 계열 길이는 **3~4** | 어텐션 행렬이 4×4까지면 한 화면에 값까지 들어간다 |

### 값의 크기가 서로를 지운다 — 실제로 밟았다

d_model=4에서 낱말 값을 1로 두고 √4=2를 곱하면 임베딩은 ±2다.
그런데 위치 인코딩은 −1~+1을 오간다. 세 번째 자리의 `cos(3)=−0.99`가 낱말 뜻을 **거의 지웠다**.
논문 크기(√512≈22.6 대 ±1)에서는 없는 문제다. 줄여서 생긴 부작용이다.

→ 낱말 값을 **2**로 올려(곱하면 4) 비를 4:1로 맞췄다. 그리고 그 사실을
**영상에서 밝힌다**("위치 인코딩이 크게 느껴지는 건 크기를 줄인 부작용입니다").

### 점수가 포화되면 softmax를 가르칠 수 없다

값이 ±4까지 가면 내적이 16까지 오르고, `÷√d_k` 뒤에도 softmax가 `1.00 / 0.00`으로 굳는다.
어텐션이 "얼마나 더 보는가"를 보여주려면 **가중치 행렬의 계수를 0.5로** 낮춘다.
이건 그 자체로 좋은 교육 포인트다 — 어텐션의 날카로움은 가중치 크기가 정한다.

## 2. 반올림 규약 — 이게 이 시리즈의 핵심 장치다

**각 단계의 결과를 표시 자릿수(둘째 자리)로 반올림한 뒤, 그 값을 다음 단계에 넣는다.**

```python
DP = 2

def q(x):                      # 다음 단계로 넘기기 전에 자른다
    return np.round(np.asarray(x, dtype=np.float64), DP)
```

안 하면 어떻게 되나: 화면엔 두 자리를 띄우고 속으로 열 자리로 계산하면, 시청자가
화면 숫자로 따라 계산한 값이 서너 단계 뒤에 어긋난다. 그러면 "따라 계산해 보세요"가 거짓말이 된다.

대신 비용이 생긴다. **그 비용을 재서 화면에 올린다.**

```python
# 같은 코드를 DP=12로 한 번 더 돌려 차이를 잰다
```

Transformer 예시에서는 인코더 출력 최대 차이 0.0134, 첫 로짓 0.0317이었고
**뽑히는 낱말은 네 스텝 모두 같았다**. 가장 아슬아슬한 결정의 여유(1등−2등)가 0.83이라
반올림 오차의 스무 배가 넘는다는 것까지 검산 편에서 보여준다.

> 여유가 오차의 10배 미만이면 가중치를 다시 잡는다. 시청자가 반올림 자리를 하나
> 다르게 잡았을 때 답이 뒤집히면 안 된다.

## 3. 가중치는 "학습한 값"이 아니라 "우리가 정한 값"이다

전부 `0, ±0.5, ±1, ±2` 로만 둔다. 그래야 손으로 곱한다.
그리고 **화면과 노트북에서 그대로 밝힌다** — 번역 실력을 보여주는 예시가 아니라
부품이 무슨 일을 하는지 보여주는 예시라고.

### 축마다 뜻을 하나씩 맡긴다

d=4라면 예를 들어 `0=주어 · 1=장소 · 2=이동 · 3=제어(시작/끝)`.
그러면 "이 헤드는 이동 동사가 장소를 찾는 헤드"처럼 **행렬을 말로 읽을 수 있다.**
행렬 하나하나가 "어느 축을 골라 어디로 옮기는가"가 된다.

### 손으로는 못 찾는다 — 탐색으로 확정한다

역할을 심는 것까지는 손으로 되지만, **끝까지 원하는 출력이 나오는 조합**은 손으로 못 찾았다.
격자 탐색을 돌렸다(4.8만 조합, 1분). 목표 출력이 나오는 조합만 남기고
**결정 여유(1등 로짓 − 2등 로짓)의 최솟값이 가장 큰 것**을 골랐다.

```python
for a, b, c, ... in itertools.product(...):
    W_O = np.array([[a, 0, 0, 0], ...])
    seq, steps = run_decoder(enc)
    if seq[1:] == TARGET:
        margins = [top1 - top2 for st in steps]
        found.append((min(margins), params, margins))
found.sort(key=lambda t: -t[0])      # 여유가 큰 순
```

탐색 공간은 **의미 있는 자리만** 연다. 전부 열면 해석 불가능한 행렬이 나와서
"이 −2는 무슨 뜻인가"를 화면에서 설명할 수 없게 된다.

## 4. 실제로 막혔던 세 가지 (Transformer 기준, 다른 모델에도 비슷하게 온다)

### ① 잔차 + 가중치 공유 = 직전 낱말이 계속 1등

출력 사영이 입력 임베딩과 가중치를 공유하면(§3.4), 잔차에 남은 **직전 토큰**이
로짓 1등을 먹는다. 같은 낱말이 무한 반복된다.

→ 해법: `W_O`에 억제 항을 하나 넣는다. "이동 축을 가져오면 주어 축을 깎아라"(계수 −2).
실제 모델도 이런 억제를 학습으로 익힌다고 화면에서 밝힌다.

### ② 끝내는 신호를 만들 데가 없다

`<eos>`를 낼 근거가 모델 안에 없었다. FFN에 "장소를 말했으면 끝내라" 같은 규칙을
심어 봤지만, 같은 조건이 한 스텝 앞에서도 켜져서 문장을 잘라먹었다.

→ 해법: **원문 끝에도 `<eos>`를 붙인다**(실제 번역 모델이 하는 방식이다).
그러면 디코더가 "원문의 끝을 보고" 끝낼 수 있다. 헤드 하나의 키를 `−e3`로 두어
제어 축이 음수로 큰 자리를 찾게 했다. 구조가 더 정직해지면서 문제도 풀렸다.

### ③ 부품이 아무 일도 안 하면 가르칠 게 없다

FFN을 `0.5·x` 항등에 가깝게 두었더니 LayerNorm이 그걸 도로 지워서
**입력과 출력이 완전히 같았다.** 화면에 올릴 게 없다.

→ 해법: 양수와 음수를 **다르게** 다룬다(`0.5·x⁺ + 0.25·x⁻`).
그 비대칭이 곧 비선형이고, ReLU 뉴런이 두 벌 필요한 이유까지 한 화면에서 보인다.

## 5. 불변량은 수학 검산 + **대본의 주장**까지

`analysis/`가 실패하면 렌더가 진행되지 않게 한다. 수학적 검산만 넣지 말고,
**대본이 하는 말**도 불변량으로 박아 둔다. 대본을 고치다 숫자가 어긋나는 것을 잡아준다.

```python
"attention_rows_sum_to_one":        ...,   # 수학
"causal_mask_blocks_the_future":    ...,
"layernorm_output_has_zero_mean":   ...,
"decoder_produces_target_sentence": ...,   # 예시가 성립하는가
"rounded_path_matches_float":       ...,   # 반올림 규약이 안전한가
"verb_attends_place_most":          ...,   # ← 대본이 "간다가 학교에를 본다"고 말한다
"word_order_is_reordered":          ...,   # ← 대본이 "어순이 뒤집힌다"고 말한다
"repo_matches_within_rounding":     ...,   # 실제 구현과의 차이
```

Transformer 예시는 14개였다. 하나라도 false면 `SystemExit(1)`.

## 6. 실제 구현과 대조한다 (검산 편의 뼈대)

같은 가중치를 **상류 저장소의 모듈에 그대로 실어** 돌린다. 드롭아웃은 `eval()`로 끈다.

```python
mha = MultiHeadAttention(N_HEAD, D_MODEL, D_K, D_K, dropout=0.0).eval().double()
mha.w_qs.weight.copy_(T(WQ).T)        # nn.Linear는 가중치를 뒤집어 저장한다
```

차이가 반올림 폭 안이면(우리는 0.0134) 그 숫자 자체가 검산 편의 결론이 된다.
**구조가 같은지도 함께 확인한다** — post-LN인지 pre-LN인지, bias가 있는지.
다르면 그건 결함이 아니라 "논문과 구현이 갈리는 지점"이므로 화면에서 짚는다.

## 7. 워크시트 노트북 — 정답을 손으로 옮겨 적지 않는다

영상과 같은 순서로 빈칸을 놓고, 시청자가 넣은 값을 맞춰 준다.

```python
check("X", my_X)      # → 맞았습니다 / 다릅니다 + 차이 표시
answer("X")           # → 막혔을 때 정답만
```

정답표는 **`analysis/walkthrough.py`를 통째로 첫 셀에 실어** 노트북 안에서 다시 돌려 만든다
(`assets/walkthrough_template/build_worksheet.py` 참고). 분석을 고치면 노트북 정답도 같이 바뀐다.
`--check`로 코드 셀만 이어붙여 실행 검증한 뒤 `.ipynb`를 쓴다.

노트북에는 **예시 가중치 표를 전부 출력하는 셀**을 넣는다. 종이에 옮겨 적고 계산해야 하니까.

## 8. 화면 배치 — 이 시리즈에서만 나오는 함정

표와 계산 줄이 화면의 전부라 자리 다툼이 유난히 잦다.
`assets/walkthrough_template/wtcommon.py`의 헬퍼를 쓰되, 다음을 지킨다.

- **표의 윗변 y를 먼저 계산하고** 계산 줄은 그 위에서만 논다.
  `numtab` 4행(cell_h=0.56)을 `DOWN*1.5`에 두면 윗변이 대략 y=−0.05다.
- 계산 줄 두 벌을 동시에 띄우려면 `UP*2.2`와 `UP*1.05`처럼 **1.1 이상** 떼어 놓는다.
- **강조 사각형은 반드시 변수로 잡는다.** `self.playw(Create(row_box(tab, 2)))` 처럼
  인라인으로 만들면 표를 지운 뒤에도 빈 사각형만 남는다(실제로 3곳에서 밟았다).
- 긴 벡터 줄은 만들 때 폭을 재서 줄인다(`fit`). 벡터 셋이 한 줄에 들어가면 잘린다.
- 막대 이름표는 **막대·값라벨을 통틀어 가장 아래**보다 더 아래에 둔다. 0선 바로 아래에
  고정하면 음수 막대의 값 라벨과 겹친다.
- 구간 제목(`scene_title`)과 본문 제목에 **같은 문구**를 쓰지 않는다. 화면에 두 번 뜬다.
- 화면 위쪽에 캡션을 두려면 구간 제목을 먼저 내린다.

## 9. 정직성 — 이 시리즈에서 특히 지킬 것

장난감 예시는 "이렇게 하면 번역이 된다"는 인상을 주기 쉽다. 그래서 **화면에서 밝힌다.**

- 가중치는 학습한 값이 아니라 우리가 정한 값이다
- 탐욕적 디코딩을 쓰지만 **논문은 빔 서치**를 쓴다(설정값까지 화면에)
- 위치 인코딩이 커 보이는 건 **크기를 줄인 부작용**이다
- `W_O`가 항등인 것, 두 언어가 같은 축을 쓰는 것도 우리 선택이다
- 층은 1개고, 학습·드롭아웃·라벨 스무딩은 다루지 않았다

한 줄로: **줄인 것은 크기뿐, 구조와 수식은 논문 그대로**임을 반복해 말하고,
줄여서 생긴 왜곡은 그때마다 짚는다.
