# video-transcript-notion

강의·회의 **영상 폴더 + 자막**을 **"차시 1개 = 노션 페이지 1개"** 로 대량 구축하는 Claude Code 스킬입니다.
영상은 구글드라이브(rclone)에 올려 임베드하고, 대본은 그 **바로 밑**에 타임스탬프와 함께 붙입니다.
**546차시 / 70GB 를 실제로 완주한 파이프라인**을 그대로 담았습니다.

## 결과물 모양 (차시 1개 = 페이지 1개)
```
🎓 7주차 · 003차시 · 12:14 · 딥러닝1        ← 정보 callout
[영상 재생]                                  ← 맨 위, 구글드라이브 embed
─────────
🎙 강의 대본 (87문장)
[00:00] 앞에서는 가중치를 찾는다고 얘기했는데…
[00:14] 실제로는 가중치를 계속 업데이트해서…
```
- 대본은 **강사가 실제로 한 말**만 담습니다(`**[HH:MM:SS]** 문장` 패턴만 추출 → 화면 OCR·코드블록은 자동 제외).
- 슬라이드 이미지·PPT 요소는 넣지 않습니다. 그게 필요하면 자매 스킬 `pdf-to-notion` 을 쓰세요.

## 언제 자동 호출되나
"강의 영상이랑 대본 노션에 정리해줘", "영상마다 자막 달아서 노션에", "전사한 거 노션 DB로 구축",
"차시별로 영상+텍스트 페이지 만들어줘", "영상 대량 업로드해서 노션에 임베드" 등.
> 노션 영상 화질이 왜 제각각인지(드라이브 변환 대기 vs 원본 저화질) 물을 때도 이 스킬이 답합니다.

## 설치
저장소 루트 README의 설치 안내를 따라 이 폴더를 `~/.claude/skills/video-transcript-notion/` 에 복사하세요.

## 사전 준비
- **Python 3.10+** (표준 라이브러리만 사용. 대시보드 프로세스 표시에만 `psutil` 선택)
- **rclone** + Google Drive remote — 영상 업로드·공개 링크
- **Notion 통합 토큰** — 대상 DB가 통합앱과 **연결(Connections)** 돼 있어야 함
- **ffprobe**(선택) — 메타데이터에 길이가 없을 때 실측, 화질 진단(`--local`)

## 사용 절차 (`scripts/`)
작업 폴더에 `config.json` 을 만들고(→ [`references/CONFIG.md`](./references/CONFIG.md)) 순서대로 실행합니다.
모든 스크립트는 `--work <작업폴더>` 를 받고 산출물은 `<작업폴더>/_out/` 에 쌓이며, **전부 멱등**이라 중단 후 다시 돌리면 이어집니다.

| 단계 | 스크립트 | 하는 일 |
|------|----------|---------|
| 0. 기준선(선택) | `06_verify.py --baseline` | 건드리면 안 되는 원본 DB의 수정시각 기록 → 나중에 "무변경" 증명 |
| 1. 스캔 | `01_scan.py` | `<그룹>/<파일>.mp4` + 자막(.merged.md/.vtt/.srt) 파싱 → `units.json` |
| 2. 업로드 | `02_upload_videos.py --detach` | 드라이브 업로드. **정체 감시 워치독 내장**, 남은 파일 0까지 라운드 반복 |
| 3. 페이지 생성 | `03_build_pages.py` | 차시별 노션 페이지. 영상 자리는 ⏳ 로 두고 **업로드를 기다리지 않음** |
| 4. 영상 채우기 | `04_sync_videos.py --loop --detach` | 올라오는 대로 ⏳ → `embed` 교체 (10분 주기, 다 채우면 종료) |
| 5. 대본 보강(선택) | `05_fill_missing.py` | 뒤늦게 전사한 대본을 기존 페이지에 삽입 |
| 6. 검증 | `06_verify.py` | 노션 실측 행수·대본·영상 커버리지 + 무작위 페이지 실물 점검 |

**부가 도구**

| 스크립트 | 하는 일 |
|----------|---------|
| `dashboard.py --detach` | `http://localhost:8765` 실시간 진행 대시보드(진행률·속도·ETA·정체 횟수·그룹별 막대) |
| `probe_quality.py` | 드라이브 **변환 상태** 조사 — 저화질 고정이 "대기 중"인지 판별 |
| `probe_quality.py --local` | 로컬 **원본 해상도** 조사 — 개선 불가한 저화질 목록 |

## 핵심 설계 (왜 이렇게 짰나)
- **페이지 먼저, 영상 나중.** 노션 블록 append 가 `after` 파라미터를 지원해서 가능합니다. 70GB 업로드가 끝날 때까지 기다릴 이유가 없습니다.
- **업로드는 라운드 반복.** 그룹별로 순회하며 N회 재시도 후 넘어가면 **미완성 그룹을 조용히 건너뜁니다**(실제로 겪음). 전체를 대상으로 남은 파일이 0이 될 때까지 반복해야 합니다.
- **워치독 필수.** rclone 이 구글드라이브 업로드 중 수 GB 지점에서 정체합니다(8시간에 22번). 3분간 전송량이 안 늘면 죽이고 재개합니다. `copy` 는 멱등이라 안전합니다.

## ⚠️ 핵심 주의사항 (실패 방지)
전체 목록과 실측 근거는 [`references/GOTCHAS.md`](./references/GOTCHAS.md) 에 13개 항목으로 정리돼 있습니다.

- **Notion API 는 통합앱당 ~3 req/s.** 병렬 호출하면 429가 나고 **한 번 걸리면 몇 분간 전체가 막힙니다.** 반드시 `vt_common.api()` 사용(스로틀·429 대기 내장).
- **업로드에 대역폭 상한(`--bwlimit`) 필수.** 안 걸면 회선을 독점해 Notion 호출까지 굶어 죽습니다(실측: 두 번 다 ~185MiB에서 정지).
- **영상 임베드는 `embed` 블록.** `video` 블록은 Google Drive 링크를 거부합니다.
- **드라이브 공개는 폴더 단위 1회**(`rclone link --expire 0 <폴더>`). 파일별 link는 수백 개면 수십 분 걸립니다.
- **`--stats` 는 `1m`.** `5m` 이면 워치독이 정체를 못 읽습니다.
- 노션 **100블록/요청**(중첩 포함 계산 → 85로 보수적), **rich_text 2000자/블록**(대본은 1800자 단위 분할).
- **대본이 없으면 지어내지 않습니다.** `🎙 강의 대본 — 없음` 으로 남기고 나중에 5단계로 채웁니다.

## 화질이 제각각일 때
노션에서 어떤 영상은 1080p, 어떤 건 320p 고정으로 보이는 현상은 **원인이 두 개**입니다. 구분해서 답해야 합니다.

| 원인 | 판별법 | 해결 |
|------|--------|------|
| 드라이브가 아직 변환 중 | Drive API `videoMediaMetadata` 가 비어 있음 (`probe_quality.py`) | **기다리면 저절로.** 로컬에서 할 일 없음 |
| 원본이 애초에 720p 이하 | 로컬 ffprobe 높이 < 1000 (`probe_quality.py --local`) | 영구적. 업스케일해도 정보는 안 생김 |

> 구글드라이브는 업로드 후 백그라운드로 360p → 480p → 720p → 1080p 순으로 변환하며, 대량 업로드 직후엔 대기열이 밀립니다.
> 실측 사례: 546개 중 **변환 대기 118개 + 원본 720p 이하 33개**가 동시에 존재했습니다.
