# 영상 + 대본 → Notion

영상 폴더와 자막을 **차시 1개 = 페이지 1개** 로 노션에 구축한다.
546차시 / 70GB 를 실제로 완주한 파이프라인이다.

## 결과물 (페이지 1개)

```
🎓 7주차 · 003차시 · 12:14 · 딥러닝1        ← 정보 callout
[영상 재생]                                  ← 맨 위, 구글드라이브 embed
─────────
🎙 강의 대본 (87문장)
[00:00] 앞에서는 가중치를 찾는다고 얘기했는데…
[00:14] 실제로는 가중치를 계속 업데이트해서…
```

**대본은 영상 바로 밑에 온다.** 슬라이드 이미지·PPT 요소는 넣지 않는다.

## 시작 전에 확인할 것

작업을 시작하기 전에 **반드시** 아래를 확인한다. 추측하면 실패한다.

1. **입력 폴더 구조** — `<source_dir>/<그룹>/<basename>.mp4` + 같은 이름의 자막 파일
2. **대상 Notion DB** — 통합앱에 공유돼 있는가, title 속성 이름이 무엇인가, child DB 구조인가
   → `references/CONFIG.md` 의 "대상 Notion DB 구조 파악하기" 를 그대로 따른다
3. **그룹 ↔ Notion 주차 대응** — 한 칸씩 밀리는 경우가 실제로 있다. 사용자에게 대응표를 확인받는다
4. **rclone remote** 가 설정돼 있고 드라이브 여유 용량이 있는가

`references/CONFIG.md` 를 보고 작업 폴더에 `config.json` 을 만든 뒤 진행한다.

## 실행 순서

모든 스크립트는 `--work <작업폴더>` 를 받고, 산출물은 `<작업폴더>/_out/` 에 쌓인다.
전부 **멱등**이라 중단 후 다시 돌리면 이어서 진행된다.

```bash
# 0. (선택) 원본 DB 무변경 증명용 기준선 기록
python 06_verify.py --work W --baseline

# 1. 폴더 스캔 + 자막 파싱 → units.json
python 01_scan.py --work W

# 2. 영상 업로드 — 수 시간 걸리므로 분리 실행 (워치독 내장)
python 02_upload_videos.py --work W --detach

# 3. 페이지 생성 — 업로드를 기다리지 않는다. 영상 자리는 ⏳ 로 두고 나중에 채운다
python 03_build_pages.py --work W --dry     # 먼저 확인
python 03_build_pages.py --work W

# 4. 영상이 올라오는 대로 ⏳ 자리를 embed 로 교체 (다 채울 때까지 10분마다)
python 04_sync_videos.py --work W --loop --detach

# 5. (선택) 뒤늦게 전사한 대본 채우기
python 01_scan.py --work W && python 05_fill_missing.py --work W

# 6. 최종 검증 — 완료를 선언하기 전에 반드시
python 06_verify.py --work W
```

진행 상황을 눈으로 보려면: `python dashboard.py --work W --detach` → http://localhost:8765

## 반드시 지킬 것

`references/GOTCHAS.md` 에 실측 근거와 함께 정리돼 있다. 작업 전에 읽는다. 핵심만:

- **Notion API 는 ~3 req/s.** 병렬 호출 금지. 반드시 `vt_common.api()` 를 쓴다(스로틀·429 처리 내장)
- **업로드에 대역폭 상한을 건다.** 안 걸면 회선을 독점해 Notion 호출이 굶어 죽는다
- **영상 임베드는 `embed` 블록.** `video` 블록은 Drive 링크를 거부한다
- **페이지를 먼저 만들고 영상은 나중에 채운다.** 블록 append 의 `after` 파라미터로 가능하다
- **완료 선언 전에 `06_verify.py`.** 노션에서 실제로 세어 보고, 무작위 페이지를 열어 확인한다

## 자주 받는 질문 — 화질이 왜 다른가

노션에서 어떤 영상은 1080p 인데 어떤 건 320p 로만 보인다는 질문을 받으면,
**원인이 두 개**이므로 구분해서 답한다. `python probe_quality.py --work W` (드라이브 변환 상태)
와 `--local` (원본 해상도)로 둘 다 조사한 뒤 답한다.

| 원인 | 해결 |
|---|---|
| 드라이브가 아직 변환 중 | **기다리면 저절로.** 로컬에서 할 일 없음 |
| 원본이 애초에 720p 이하 | 영구적. 업스케일해도 정보는 안 생김 |

## 대본이 없는 차시

자막 파일이 없으면 페이지는 만들되 `🎙 강의 대본 — 없음` 으로 남긴다.
**절대 지어내지 않는다.** 나중에 전사한 뒤 `05_fill_missing.py` 로 채운다.

OpenAI 로 전사한다면 `gpt-4o-transcribe`(문장 품질) + `whisper-1`(타임스탬프) 를 함께 쓰고
difflib 로 정렬하는 게 정확하다. 전문용어 목록을 prompt 에 넣으면 정확도가 크게 오른다.

## 다른 형태가 필요하면

- 슬라이드 이미지 + 설명 2단 → `pdf-to-notion`
- 코드 노트북 한 줄 풀이 → `code-guidebook-notion`
- 슬라이드와 대본을 **정렬**해 붙이고 싶다면: 강사는 자료를 순서대로 넘기므로 슬라이드 번호가
  시간에 대해 단조 증가한다. 이 제약을 넣은 DP(스코어 = IDF 가중 코사인)로 풀면 그리디보다
  훨씬 안정적이다(실측 단조 위반 0건). 차시 제목의 `(실습)` 표시로 이론 자료와 실습 노트북을
  가르는 것도 효과적이었다.
