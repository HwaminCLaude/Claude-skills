# 나레이션 말투

자막이 곧 화면 글자이므로 큐 문장(`t`, `say`)에 적용한다. 수치 출처는 참고 영상의 나레이션 분석 자료(스킬 작성자 내부 자료)다.

## 화자

- 1인칭 없이 대화체만 쓴다(사용자 확정). '저는', '제가', '우리' 같은 말을 쓰지 않는다. 농담도 넣지 않는다. 린트가 `E5`로 잡는다(아래 '린트가 세는 것').
- 예시 코퍼스에 나오는 채널 이름 같은 브랜드 요소는 `t`에도 `say`에도 쓰지 않는다.

## 문장 끝: 습니다체 기본, 2~3문장마다 '~죠?'·'~까요?'

참고 영상 나레이션의 기본 어미는 습니다체다(문장의 60.5%). 다만 습니다가 길게 이어지지 않게 2~3문장마다 확인 '~죠?'나 질문 '~까요?'로 끊어 듣는 사람에게 말을 건다(습니다 평균 연속 3.0문장). 이 말투를 따른다(2026-10-28 사용자 결정).

- **기본 어미는 '습니다·ㅂ니다'**: 문장 끝의 45~65%.
- **2~3문장마다 끊기**: 확인 '~죠?'(방금 보여 준 것에 동의를 구함)나 질문 '~까요?'(다음 화면이 답함)를 넣는다. 습니다는 4문장까지만 잇고, 다섯 번째는 '~죠?', '~까요?', '~거든요', '~고요'로 바꾼다.
- 질문('?'로 끝남)은 문장의 15% 이상(참고 영상 약 22%), '~죠'는 10~20%(참고 영상 12.1%).
- 해요체('~요')는 나열을 잇거나('~고요') 이유를 붙일 때('~거든요') 짧게 섞는다. 문장 끝의 기본값으로 쓰지 않는다. '~요'와 '~죠'만으로 편을 채우면 E3·E4 WARN이 난다.
- '명사 + 입니다' 서술이 이어지지 않게 한다. 동사로 끝내야 말처럼 들린다(참고 영상 '입니다' 서술 15%).
- 구간마다 자문자답을 1번 이상 넣는다. 질문 다음 큐에서 화면이 바뀌며 답한다(`rel`은 `change`, `point`, `carry` 등).

리듬 예(`/`는 큐 경계):

> LoRA는 원래 가중치를 그대로 둡니다 / 그럼 학습은 어디서 할까요? / 옆에 붙인 작은 행렬 두 개에서 합니다 / 둘을 곱하면 원래와 같은 크기가 되죠? / 그래서 이 둘만 바꾸면 됩니다

## 쓰지 않는 표현

- 퀴즈 삼단('…일까요? / 아닙니다 / …일 뿐입니다').
- 문어 연결어미: ~며, ~므로, ~하여, ~으로써, ~에 해당합니다.
- 첫 문장에서 편 번호나 제목 읽기.
- 진행 멘트: '~짚겠습니다', '다음 편에서 이어 갑니다'.
- 부정 단정('아닙니다/않습니다')은 구간당 1번 이하.

## 써야 하는 표현

- 화면을 가리키는 말(여기, 이렇게, 이 칸, 아까)을 1천 자당 4번 이상.
- 숫자는 크기 감각으로 말한다. 셋째 자리 이상 소수는 그 값이 답일 때만.
- 문장 길이를 고르게 맞추지 않는다(변동계수 0.5 이상). 5~12자 짧은 문장을 섞는다.

## 큐로 쪼개기

한 문장을 자막 1줄(26자 이하) 큐 여러 개로 나눈다. 쉼표에서 끊으면 큐 끝에 쉼표를 남긴다. 각 큐에는 화면 박자가 1개 이상 있어야 한다.

## 린트가 세는 것(편 통계)

`lint.py`는 `shots.json`의 큐를 세어 편 단위로 본다. 모두 WARN이고 ERROR가 아니다. 기준값은 설계 §5.6·§5.7·§7 A4·§2.1 G4와 같다.

- `E1`(key)은 **큐** 단위로 센다. 큐가 10개 이상일 때만 낸다.
- 말투 비율 `E2`~`E4`와 연속 `E8`은 **문장 끝 큐** 단위로 센다. 문장 끝 큐는 쉼표로 끝나지 않고, 물음표·느낌표나 종결 어미(`니다 요 죠 다 까` 등)로 끝나는 큐다. 'LoRA는요,'처럼 쉼표로 끝난 큐와 '입력이 지나가는 이 길은'처럼 어미 없이 끊긴 큐는 문장 중간이라 세지 않는다. 한 문장을 큐 여러 개로 쪼개도 비율이 흔들리지 않게 하기 위해서다. `E2`~`E4`는 문장 끝 큐가 8개 이상일 때만 낸다.

| 규칙 | 세는 것 | 기준 |
|---|---|---|
| `E1` | `key`(노랑)가 있는 큐 비율 | 10~30% |
| `E2` | 문장 끝 큐 중 `?`로 끝나는 비율 | 15% 이상 |
| `E3` | 문장 끝 큐 중 끝의 `?!,.~…`를 떼고 `죠`로 끝나는 비율(`~죠?`는 E2와 E3에 함께 든다) | 10~20% |
| `E4` | 문장 끝 큐 중 끝 문장부호를 떼고 `니다`로 끝나는 비율(습니다·ㅂ니다) | 45~65% |
| `E5` | `t`나 `say`에 낱말 머리로 나온 `저는 제가 저도 저를 저희 제게 내가 우리`(큐마다 1줄, '문제가'처럼 낱말 안에 든 것은 아님) | 0회 |
| `E6` | 캔버스 해설용 한글 글자 수 ÷ 편 길이(분) | 20자 이하 |
| `E7` | 캔버스 문자열과 자막 `t`의 연속 4낱말 겹침(§5.5-9) | 0회 |
| `E8` | 습니다체 문장 끝 큐가 이어진 길이(다섯 번째 큐에서 1줄) | 4개 이하 |

- 자막 글자 수(26자 이하 `C1`), 끝 마침표(`C2`), 금지 기호(`C3`), 같은 `rel` 4큐 초과(`C5`)는 큐 규칙이 따로 본다. 편 중앙값 15~20자(A4)는 아래 `stats:` 줄로 확인한다(WARN 없음).
- 자문자답, 문어 연결어미, 화면 가리키는 말 1천 자당 4번은 린트가 보지 않는다. 대본을 쓰면서 직접 지킨다.

lint는 표준 오류 끝에 편 통계 한 줄을 찍는다. 3단계에서 이 줄로 비율을 확인한다. 예:

```
stats: cues=49 sentences=34 len_max=20 len_median=16 key=24.5% question=20.6% jyo=14.7% supnida=55.9% supnida_run=3 canvas_hangul_per_min=3.7
```

`cues` 큐 수, `sentences` 문장 끝 큐 수, `len_max`·`len_median` 자막 글자 수 최대·중앙값, `key` E1 비율, `question`·`jyo`·`supnida` E2~E4 비율(문장 끝 큐 기준), `supnida_run` 습니다체 최장 연속, `canvas_hangul_per_min` 캔버스 해설 한글 분당 글자 수(편 길이를 모르면 `-`).

## 고치기 전후

1~3행은 기존 영상의 문어체 나레이션을 고친 것이고, 4행은 예시다. '후' 열은 모두 습니다체를 기본으로 두고 '~죠?'·'~까요?'로 끊었다.

| 전(문어체 나레이션) | 후(큐, `/`는 큐 경계, `[ ]`는 `key`) |
|---|---|
| 로라는 기반 가중치를 고정합니다. 첫 경로는 기존 가중치에 입력을 곱하며, 학습 중에도 이 가중치 값은 바뀌지 않습니다. | LoRA는 먼저 / 원래 있던 W를 [그대로 얼려] 둡니다 / 입력이 지나가는 이 길은 / 학습이 끝날 때까지 바뀌지 않죠 |
| 변화량은 두 작은 행렬의 곱입니다. 랭크와 스케일 계수가 형태와 크기를 정하고, 학습은 이 어댑터를 조정합니다. | 그럼 학습은 어디서 할까요? / 옆에 붙인 [얇은 행렬 두 개]에서 합니다 / B와 A를 곱하면 W와 같은 모양이 됩니다 / 얼마나 얇은지는 r이 정하고, / 얼마나 세게 더할지는 / α를 r로 나눈 값이 정합니다 |
| 기반 경로에 변화량 경로를 더해 출력합니다. 같은 기반에 목표별 어댑터를 적용하여, 공통 출발점에서 감독 목표를 비교합니다. | 출력은 두 길을 [더한 값]입니다 / W 위에 ΔW를 얹는 거죠 / 그래서 W는 하나만 두고 / 어댑터만 갈아 끼우면 / 목표가 다른 세 모델을 / 같은 출발점에서 비교할 수 있습니다 |
| 어텐션은 쿼리와 키의 내적으로 가중치를 계산하며, 이 가중치로 값 벡터의 가중합을 구합니다. | 단어 하나가 다른 단어를 볼 때 / 얼마나 볼지는 어떻게 정할까요? / 쿼리와 키를 [내적]해서 정합니다 / 값이 클수록 더 많이 보는 거죠 / 그 비율대로 값 벡터를 섞습니다 |

- 원문 사례의 `W₀`는 `₀`(U+2080)가 Noto Sans KR에 없어 자막 글리프 검사(`C7`)에 걸린다. 위 표에서는 `W`로 적었다. 화면에서는 Tex `W_0`로 보여 준다.
- `α`, `Δ`는 Noto Sans KR에 있다(2026-10-27 확인). 다른 기호는 `C7`로 확인하고, 없으면 풀어 쓴다.
