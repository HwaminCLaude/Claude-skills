# 작성 규칙

채용 담당자가 각 페이지에서 30초 안에 "무엇을, 어떻게, 결과가 얼마나"를 읽게 하는 것이 목표다.

## 절대 규칙

1. **수치는 산출물에 있는 것만.** README·결과 파일·노트북 출력·논문 원고·수료증·상장·릴리즈 노트에서 그대로 옮긴다.
   없으면 규모·과정 수치(데이터 건수, 테스트 수, 쪽수)로 대체하거나 "측정하지 않았습니다" 한 문장으로 끝낸다.
   계산해서 만든 퍼센트(예: 평균 차이를 직접 나눈 값)는 쓰지 않는다. 원본에 있는 표현(+11.1 s)으로 둔다.
2. **비용을 숨기지 않는다.** 이득 수치 옆에 비용·조건(n, 중앙값, 단일 런)을 같은 문장이나 같은 표에 적는다.
3. **공동 작업은 역할을 분리한다.** 팀 성과 수치는 "팀 결과"로, 본인 몫은 역할 문장으로.
4. **이모지 금지.** 콜아웃(기본 아이콘이 이모지) 대신 인용(quote)·표·제목 블록을 쓴다. 페이지·DB 아이콘도 넣지 않는다.
5. **작성 과정을 드러내는 문장 금지.** 아래 문구와 그 변형은 쓰지 않는다.
   - "본 페이지의 … 는 YYYY-MM-DD 기준 … 에서 정리했습니다", "근거:", "근거 수준:", "출처: … (열람일)"
   - "기재 예정", "측정 예정 + 측정 계획", "(월 단위 기록)", "확인 필요"
   - "… 하지 않았습니다. 측정 계획: …" → 앞 문장만 남긴다.
   근거가 필요한 수치는 각 페이지의 "산출물" 절에 **링크**로 둔다(저장소 README, ERRATA, 설계서). 문장으로 설명하지 않는다.
6. **사용자가 만든 구조를 존중한다.** 섹션(탭) 이름과 소속은 그대로 두고 데이터 소스 이름·오타·빈 행만 고친다.
   재분류가 필요해 보이면 보고서에 제안만 적는다.

## 페이지 본문 구성

1. 첫 블록 = 대표 이미지(있으면 그대로 둔다. 갤러리 썸네일이다)
2. 요약 quote: `**long_result**` / 기간 / 역할 / 기관·주최 / 기술 / 링크 — 각 줄은 `줄바꿈` 으로 한 블록
3. 기존 본문(건드리지 않는다. 보일러플레이트 문장만 `remove_text_contains` 로 삭제)
4. divider 뒤에 추가 절(대표 항목만): 핵심 결과 표 → 문제 → 접근 → 비용과 한계 → 정확성·재현성(있으면) → 배운 점 → 산출물(링크)
5. 관련 자료: 옛 라벨 링크를 불릿으로

## 날짜 표기

- 속성은 ISO(YYYY-MM-DD). 월만 알면 1일~말일. 종료 미정이면 end 를 비우고 상태 "진행 중".
- 본문에서는 2026.05 처럼 연월. 수료증·상장에 적힌 날짜가 있으면 그것을 쓴다(기사 날짜가 아니라).

## 문장 톤

- 1인칭 서술은 Highlights 가 아니라 페이지 본문에서만 필요할 때.
- "~했습니다" 종결, 한 문장에 숫자 1~2개.
- 영문 고유명사(SGLang, Transformers)는 원어, 일반 용어는 한국어(영어 병기는 처음 한 번).
